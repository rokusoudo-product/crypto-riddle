## 1. 概要

情報処理安全確保支援士（SC）レベルのセキュリティ知識が、遊びながら身につく**謎解き×防衛アドベンチャー**。
プレイヤーはセキュリティ担当者として、**1マップ＝1インシデント事件**を「導入 → 探索 → 解決」の3パートで解き明かし、
攻撃手段を特定して防衛策を講じることでマップを攻略していく（全10〜20マップ想定）。
核となる手触りは「集めたヒント（カード）と暗号を**パズルのように組み合わせて**攻撃を読み解く」推理体験。

- プラットフォーム: **Web アプリ（スマホブラウザ対応）**（concept 決定を踏襲）。
- 正式名称: **仮称 crypto-riddle**。確定はゲート①判断事項（§11）。

## 2. 背景・目的

- 座学で定着しにくいセキュリティ知識を、事件解決の達成感と反復で継続学習に変える。
- 代表は 2026年11月に **ネットワークスペシャリスト（NW）試験**を受験予定。セキュリティ分野は NW でも配点が大きく、本ゲームの学習が試験対策に直結する（study_agent・NW学習計画と連携）。
- 将来的に SC 試験対策そのもの、六創堂の教育・研修コンテンツへの転用も視野。

## 3. ユーザーストーリー

- **US-1（学習者・スキマ時間）**: スマホで1事件を10〜15分で解き、SCレベルの攻撃手法を「解けた」実感とともに覚えたい。
- **US-2（学習者・弱点把握）**: 解いた事件の分野（暗号/認証/Web/インシデント対応 等）が記録され、弱点分野が分かるようにしたい。
- **US-3（学習者・物語で継続）**: 登場人物やサポート役との会話・事件の続きが気になって次のマップに進みたい。
- **US-4（監修者＝代表）**: IPA 過去問（SC 午前II・午後 直近5年）を素材に、出典を明示しつつ事件シナリオを量産・監修したい。

## 4. コアゲームループ（GDD の核）

```
事件発生（導入）
  → 現場を探索して人物/ログ/機器から手がかりを得る（ヒントカード獲得）
  → 得たカードと暗号を組み合わせて「攻撃手段」を特定（推理）
  → 正しい防衛策を選んでインシデントを解決（防衛）
  → 事件クリア＝物語が一歩進む／XP・分野習熟が加算
  → 次の事件（次マップ）へ
```

### 4.1 1マップの3パート構成（逆転裁判・ダンガンロンパ型）

| パート | 目的 | 具体 |
|--------|------|------|
| **導入** | 事件の前提提示 | 背景・登場人物・被害会社の状況をストーリーで提示。**サポート役キャラ**が事件概要と目的を説明 |
| **探索** | 手がかり収集 | 現場（人物・PC・ログ・物証）を調べ **ヒントをカード形式で獲得**。ダミーカードを混在させ取捨選択を作る |
| **解決** | 推理と防衛 | （暗号があれば）暗号解読 → **立ち絵つき会話の中で問いに2〜3択で答える対話推理**で攻撃手段を特定 → 有効な防衛策を選択。サポート役が誤答時にフォロー（会話モード＝#42。詳細は §8） |

- **サポート役ペア（得意領域は固定・逆転なし／#7）**
  - **霧島 悠（技術・男性）**: 寡黙な実力者。ログ・攻撃手法・EDR/NW・暗号。技術シーンで解説、法務シーンで質問役。
  - **橘 澪（法務・女性）**: 明晰な司令塔。法制度・報告義務・証拠能力・説明責任。法務シーンで解説、技術シーンで質問役。

## 6. シナリオ構造（フィードバック反映：物語×パズルの一体化）

- **1マップ = 1事件 = 1つの物語アーク**。導入で提示された「謎（誰が・どうやって・なぜ攻撃したか）」が、探索での人間関係・動機の解明と、暗号/技術的手がかりの解明の**両輪**で解けていく。
- 技術パズル（暗号・攻撃特定）を物語から切り離さない：カードは必ず「誰の証言／どの機器のログ」という**物語上の出所**を持ち、正解は「事件の真相」と一致する。
- **マップ間の連続性（任意）**: 事件をまたぐ横糸（黒幕・組織など）を薄く通し、次マップへの牽引にする（MVP では必須にしない。§11 判断）。

## 7. 探索・ヒントカード設計

- **調査は3系統に整理する（#7 正式採用）**: ①**ログを見る**（プロキシログ／認証ログ／EDRアラート等＝技術的事実の読み取り） ②**人に聞く**（現場担当・委託先・経営層へのヒアリング＝状況把握・関係者調整） ③**文献を引く**（CVE／ガイドライン／法令／社内規程＝根拠に基づく判断）。SC午後の「状況判断＋根拠の記述」に対応づける。
- 各マップに **調査ポイント複数**（人物・PC・ログ・物証）を上記3系統で配置。クリックで調査 → カード獲得。
- **カード種別（案）**: 証言 / ログ / 通信記録 / ニュース・外部情報 / 暗号文 / 鍵・手がかり / 対策カード（解決用）。
- **ダミーカード**を混在させ「もっともらしいが今回の直接原因ではない」引っ掛けを作る（SCで問われる“表面的に怪しい選択肢に飛びつかない”思考の訓練）。
- カード枚数・正解に必要な枚数・ダミー比率は §11 でバランス判断（プロトタイプは全10箇所・正解6/ダミー4）。

## 8. 解決パート設計（会話モード = 立ち絵つき対話で解く推理）

> **2026-09-10 会話モードへ刷新（#42・T018 プレイテスト反映）**: 本作の核は「立ち絵つきの会話の中で仮説を選び、集めた手掛かりと突き合わせて解く**対話推理**」に寄せる。カードを複数枚スロットへ配置して組み合わせる旧UI（T014）は廃止し、会話モード1本に統一する（両モード並存はしない）。暗号解読（§8.1）は解決の一ステージとして残す（本作の入口 S1 は暗号なし）。会話画面のレイアウト（下部会話ウィンドウ・中央左右の立ち絵・非発話側のグレーアウト・名札）は `DESIGN.md`「会話フレーム」節を正本とする。

### 8.1 暗号解読ミニゲーム
- 手がかりから暗号文と鍵/ヒントを得て解読（プロトタイプはシーザー暗号のシフトをライブ調整）。暗号がある場合は会話モードの前段に置く。
- **弱点対処①**: 1マップ内で**暗号を複数種・複数段組み合わせる**方向を検討（例: 古典暗号で得た文字列を鍵に別処理、ハッシュ照合、XOR、Base64 等）。暗号方式の配分（古典/現代）は §11。

### 8.2 攻撃手段の特定（会話モード・選択式）
- サポート役が「これは○○では？」と**問い**を出し、プレイヤーが**2〜3択**で答える。Yes/No 的な判断は2択、知識を要する候補は3択（#42 代表決定）。
- **判定方式（#7 維持）**: **問い単位で単一解・厳密一致**（正解の選択肢は各問い1つ）。部分点・複数正解ルートは引き続き見送る。
- **誤答フォロー**: 外すと相手が「その場合だと〜」と**理由を添えて返し**、再挑戦できる。外すたびに**解説が段階的に深くなる**（＝旧「教育的失敗」を会話内に統合。⑥失敗解説の独立画面は廃止する。§8.4）。
- **カード閲覧（無料）**: 探索で集めた手掛かり（カード）は会話中・選択中もいつでも閲覧でき、判断材料にできる（#42 代表決定）。閲覧にコストはかからない。
- **相談（コストあり）**: 詰まったら相談で、手元の手掛かりを整理した**詳細ヒント**を提示する。相談は**マップ単位で3回まで**（§8.4）。

### 8.3 防衛策の選択（会話モードの最終問い）
- 攻撃手段が定まったら、**有効な防衛策を選ぶ問い**を会話モードの最後に置く（本質的でない対策を誤答肢に）。正答で事件解決。

### 8.4 難易度・緊張感・ペナルティ（#42 で本決定）
- **弱点対処③（解決済み）**: 誤答・相談に**ペナルティを付ける**。**誤答1回ごと・相談使用1回ごとに獲得XPを減算**（下限あり＝クリア報酬を下回っても0未満にはしない）。無制限試行は許容しつつ、丁寧さに応じて報酬が変わる形にする。
- **相談上限**: **マップ単位で3回**（問い単位ではない＝2問×3回で実質無制限になるのを防ぐ）。
- ランク仕様（§11-11）が未確定のため、いま定義できる最小形として上記 XP 減算を採用する。マップ評価ランク（S/A/B 等）を新設する案は §11-11 判断とし、本 MVP では見送る。

### 8.5 問いの数・構成（当面）
- 1マップは当面「**攻撃の起点 → 初動対応**」の**2問構成**（テスト段階）。問い数・分量の物差しは §11-8／#15 の分量パラメータと連動して確定する。

## 9. ゲーム内経済・進行・クリア条件

- **報酬**: 事件クリアで XP（基礎報酬）。**誤答1回・相談1回ごとに獲得XPを減算**（下限あり。§8.4／#42）。ダミー回避・ノーヒントクリア等の追加ボーナスは案。
- **進行**: マップを順に解放。分野別（暗号/認証/Web/攻撃手法/インシデント対応/法制度/ネットワーク基盤）に習熟度を記録し弱点を可視化。
- **分野タグを7種に統一（Issue #22 決定・2026-09-09）**: 当初 spec は6分野（暗号/認証/Web/攻撃手法/インシデント対応/法制度）としていたが、
  用語カードマスタ（Issue #4／`terms/terms_core.yaml`）が NW/SC 共通シラバスのネットワーク基礎用語（TCP/IP・ファイアウォール・IDS/IPS 等）を
  扱うために独自に追加していた「ネットワーク基盤」を、シナリオ側の分野タグにも正式採用し**7種に統一**した（案2）。
  代表の NW 試験対策（2026-11、§2）という目的に整合すること、既存45語データの書き換えが不要なことを理由とする。
  値集合の単一の正本は `src/core/model/tags.ts`（zod, `SUBJECT_TAGS`）とし、シナリオ・用語カード・SaveData（分野習熟）が
  すべてこれを参照する。難易度カーブ（下記）はタグ数と独立のため、7種化による変更はない。
- **難易度カーブ（#7 決定）**: シナリオを難易度順に配置する。S1〜2＝基礎（侵入経路・初動）、S3〜6＝個別技術領域、S7〜8＝制度・組織論と総合演習。
- **クリア条件（マップ）**: 会話モードの全問い（攻撃手段の特定＋有効な防衛策の選択）に正答。
- **学習指標**: 分野別習熟、SC 合格ライン（正答率60%）対応のランク表示（concept 由来。MVP採否は §11）。
- **スコープ整理**: ドリル（午前II型）・間隔反復（復習モード）は **初期スコープ外**（リリース後追加候補）。MVP は謎解きマップ攻略に集中。

## 10. 機能要件 / 非機能要件 / 受け入れ基準 / スコープ外

### 機能要件（MVP）
- FR-1 1マップの3パート（導入/探索/解決）を通しでプレイできる。
- FR-2 探索で調査ポイントからカードを獲得し、インベントリで確認できる。
- FR-3 暗号解読ミニゲームを解ける（最低1方式、拡張余地を持つ設計）。
- FR-4 会話モードで問いに2〜3択で答えて攻撃手段を特定し、防衛策を選んでクリアできる（単一解・厳密一致は問い単位で維持）。
- FR-5 サポート役キャラが導入説明・探索誘導・誤答フォロー（外すたびに解説が深まる）・クリア解説を、立ち絵つき会話（会話フレーム）で行う。
- FR-6 事件クリアで XP・分野習熟が加算・保存される。
- FR-7 IPA 過去問を**題材の参考**にしたシナリオ・カードには、`docs/citation-policy.md` の規則に従い**「〜を参考に作成」の表記**を明示する（主表示は⑦結果画面。設問の転載・類題化はしない）。
- FR-8 MVP マップ本数（初期公開分）を用意する（本数は §11）。
- FR-9 セーブデータのエクスポート/インポートができる（iOS Safari の7日ストレージ削除対策。将来のアカウント同期の布石。plan.md §6／2026-07-29 advisor 指摘により MVP 要件化）。
- FR-10 会話モードで、集めた手がかり（カード）を会話中いつでも**無料で閲覧**でき、詰まったら**相談（マップ単位3回まで）**で詳細ヒントを得られる（§8.2／#42）。
- FR-11 誤答1回・相談1回ごとに獲得XPを減算する（下限あり。§8.4／#42）。

### 非機能要件
- NFR-1 スマホブラウザでスキマ時間に遊べる軽さ。
- NFR-2 学習履歴の永続化（端末ローカル → 将来アカウント同期）。
- NFR-3 IPA 過去問は**題材の参考としてのみ**利用し（設問の転載・言い換え類題は禁止）、参考にした過去問の表記を必須とする。規則の正本は `docs/citation-policy.md`（2026-09-10 制定、#14）。

### 受け入れ基準
- [ ] 未整理の§11判断事項が代表レビューで解決される。
- [ ] MVP スコープ（謎解きマップ攻略型・サポート役・物語一体化）が承認される。
- [ ] 承認をもって status を review→approved にし、次工程 plan.md（ゲート②）へ。

### スコープ外（当面）
- 実攻撃ツール・実環境演習（設問内で完結）。
- 対人対戦。
- ドリル/間隔反復（復習モード）。

## 11. ゲート①で判断する事項（要判断リスト）

代表レビューで一括判断する。

1. **正式名称の確定**（現在 crypto-riddle は仮称）。
2. ~~**サポート役キャラ**: 1体か複数か／性格・口調～~~ → **解決済み（#7/#8）**: 男女2名ペア（霧島 悠＝技術／橘 澪＝法務、得意領域固定）。詳細は `docs/characters.md`・§5。
3. **物語の横糸**: マップ間に黒幕・連続ストーリーを通すか（MVP必須か任意か）。
4. **暗号パズルの深さ**: 1マップで暗号を複数種・複数段組み合わせるか。古典/現代の配分。
5. ~~**解決の判定方式**～~~ → **解決済み（#7）**: MVP は単一解・厳密一致（複数正解ルート見送り）。§8.2 参照。
6. ~~**誤答ペナルティ**~~ → **解決済み（2026-09-10、#42）**: 無制限試行を許容しつつ、**誤答1回・相談1回ごとに獲得XPを減算**（下限あり）。相談は**マップ単位3回**まで。試行制限・タイマーは不採用。§8.4 参照。
7. **カードバランス**: 1マップの調査ポイント数・正解/ダミー比率の目安。
