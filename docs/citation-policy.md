# 出典表記規則（citation policy）

> spec.md §11-10（IPA過去問の出典表記の具体形式）のクローズ文書。FR-7・NFR-3 の実装規則。
> **本規則は「設問を転載しない」前提の規則である**（下記 §1）。将来、設問・図表を直接掲載する方針に変更する場合は、その時点で IPA の過去問利用規定の確認が必須になる。
> 適用範囲: **MVP（無償公開）**。六創堂の教育・研修コンテンツ等への**商用転用時は本規則を再検討する**。

## 1. 素材の利用方針（代表決定 2026-08-02）

- **過去問と同じような問題は出さない。** 設問の転載も、設問を言い換えただけの類題も作らない
- **過去問・過去の事例を参考にシナリオを作成するのはよい。** 参照するのは事実関係・技術要素・攻撃手口などの**題材**であり、成果物は六創堂のオリジナル創作である
- したがって本規則が定めるのは、引用・改変の表記ではなく**「何を参考にしたかを示す」表記**である

## 2. 禁止事項

シナリオ・カード・用語カード・クイズのすべてで、以下を禁止する。

1. IPA 過去問の**設問文・解答・解説の転載**（一部引用を含む）
2. 過去問の**図表・イラストの流用**（トレース・再作図による実質的な複製を含む）
3. **設問を言い換えただけの類題**の作成（選択肢構成の流用を含む）
4. 参照してよいのは**事実関係・技術要素・攻撃手口・事例類型・用語**に限る

## 3. 基本フォーマット

参照元の識別は次の順・表記で統一する。

```
情報処理安全確保支援士試験 令和6年度 春期 午後 問2
```

- 順序: **試験名（正式名称）→ 年度（和暦）→ 実施期（春期/秋期）→ 区分（午前II/午後）→ 問番号**
- 試験名は略称（SC 等）を画面表示に使わない（データ内部のコードとしては可）
- CBT 化・科目再編で区分名が変わった年度は、**実施当時の公式区分名**をそのまま使う

### 「参考にした」ことを示す定型句

- 文書・画面共通の定型句: **「◯◯ を参考に作成」**
- 転載・改変を前提とした表記（「〜を改変して作成」「〜より引用」等）は**使用しない**（§1 の方針により発生しない）

**表記例（シナリオ末尾・結果画面）:**

```
本シナリオは以下を参考に作成したオリジナルの創作です。
・情報処理安全確保支援士試験 令和6年度 春期 午後 問2（攻撃手口）
・情報処理安全確保支援士試験 令和5年度 秋期 午前II 問14（技術要素）
```

- 括弧内は**参照した題材の種別**（§5 の material_kind）。複数あれば箇条書き
- 参照元が無い完全オリジナルのシナリオ・カードには表記を付けない

## 4. 画面上の表示位置（DESIGN.md の8画面との対応）

| 画面 | 表示 |
|---|---|
| ⑦結果 | シナリオ単位の「参考にした過去問」ブロックを表示（§3 の表記例の形式）。**主表示位置** |
| ⑧カード図鑑（カード詳細） | そのカード・用語カードに参照元がある場合のみ、詳細表示に1行表記 |
| ③導入〜⑥失敗解説 | 表示しない（没入優先。FR-7 の「各所で明示」は⑦⑧で満たす） |
| タイトル/README | 「IPA 情報処理技術者試験の過去問題を題材の参考として使用しています（設問の転載はありません）」の包括表記 |

## 5. シナリオスキーマの出典フィールド（#3 / zod スキーマとの対応）

シナリオ・用語カードのメタ情報に `references[]`（配列・省略可）を持たせ、表示文字列はデータから生成する。

| 項目 | 型 | 例 | 備考 |
|---|---|---|---|
| `exam` | enum | `SC` | 試験区分コード。表示時に正式名称へ展開 |
| `year_jp` | string | `令和6年度` | 実施年度（和暦）。表示に使う公式表記 |
| `season` | enum | `春期` / `秋期` | CBT等で期の概念が無い場合は省略可 |
| `division` | string | `午後` / `午前II` | 実施当時の公式区分名 |
| `question` | string | `問2` | 問番号 |
| `material_kind` | enum | `攻撃手口` / `技術要素` / `事例類型` / `用語` | 参照した題材の種別 |
| `note` | string（省略可） | — | 補足 |

- **改変フラグは持たない**（§1 の方針上、転載・改変が存在しないため）
- 現行 zod スキーマ（`src/core/model/`）の出典フィールドが上記と異なる場合は、**T015（S1データ作成）着手前に**本表へ合わせる

## 6. 法制度データの出典

法制度データ（`legal/`。plan §4 によりシナリオ本体から分離）は次で表記する。

- **法令**: e-Gov の正式法令名＋条番号＋（参照した改正時点または施行日）
  例: `個人情報の保護に関する法律 第26条（令和4年4月1日施行時点）`
- **ガイドライン・基準**: 発行主体＋正式名称＋版または公表年
  例: `個人情報保護委員会「個人データの漏えい等の事案が発生した場合等の対応について」（令和4年版）`
- 法改正で差し替わる前提のため、出典は**法制度データファイル側**に持ち、シナリオからは参照のみとする

## 7. 運用

- 新規シナリオ・カードの追加時、制作者（AI生成＋代表監修）は §2 の禁止事項に該当しないことを監修時に確認する
- 本規則の変更は代表の承認を得て行い、変更履歴を本ファイル末尾に残す
